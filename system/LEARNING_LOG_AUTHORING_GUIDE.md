# Learning Log Authoring Guide

이 문서는 이전의 좋은 기록을 복제하기 위한 template이 아니다. 매 학습 세션에서 새로 생긴 evidence를 식별하고, 그 세션만의 사고 변화를 `templates/learning-log.md` 구조에 정확히 배치하기 위한 작성 기준이다.

과거 Learning Log는 현재 학습 위치와 기존 이해를 확인하는 source로만 사용한다. 과거 문장, 설명 순서, 주제별 세부 항목, checkbox 판정을 새 기록에 재사용하지 않는다.

## 1. 먼저 evidence inventory를 만든다

초안을 쓰기 전에 현재 conversation에서 다음 항목을 찾는다. 실제 evidence가 없는 항목은 만들지 않는다.

- 사용자가 직접 설명하거나 비교한 문장
- 사용자가 세운 가설과 추론 과정
- 사용자가 명시적으로 표현한 혼란, 질문, 확신하지 못한 부분
- 대화 중 드러난 factual misconception 또는 용어 혼동
- 피드백 후 사용자가 다시 설명하여 확인된 수정
- 예제, 반박, 퀴즈로 실제 확인된 이해
- 아직 검증되지 않았거나 다음 세션으로 남은 질문
- 현재 주제를 선택한 목적과 다음 학습 행동

AI가 설명한 내용은 사용자가 이해했다는 evidence가 아니다. 사용자가 수용하거나 다시 설명하지 않은 내용은 `사용자가 이해한 내용`이나 완료된 checkbox로 기록하지 않는다.

## 2. provenance를 표시한다

초안의 각 주요 주장에 대해 내부적으로 다음 중 출처를 구분한다.

- `user-stated`: 사용자가 직접 말함
- `user-demonstrated`: 자기 설명, 비교, 풀이 또는 퀴즈로 보임
- `corrected`: 초기 이해와 수정 후 이해가 모두 확인됨
- `assistant-explained`: AI가 설명했지만 사용자 확인은 아직 없음
- `open`: 질문 또는 검증 대기 상태

최종 Markdown에 이 label을 기계적으로 노출할 필요는 없다. 다만 `assistant-explained`를 `user-demonstrated`처럼 서술하거나 checkbox 완료 근거로 사용해서는 안 된다.

## 3. 세션 고유의 narrative를 구성한다

`templates/learning-log.md`의 section은 유지하되 내용의 길이, 하위 heading, 설명 순서는 현재 세션 evidence에 따라 정한다.

- `오늘 공부한 목적`: 실제 세션 목표 또는 질문을 기록한다.
- `오늘 이해한 내용`: conversation의 진행 순서보다 개념적 인과관계가 명확하도록 구성하되 사용자의 사고 흐름을 보존한다.
- `핵심 개념`: 이번 세션에서 실제 다룬 핵심만 고른다.
- `내가 처음 이해한 방식`: 사용자의 실제 초기 설명이나 가설만 기록한다.
- `오해 또는 불확실한 부분`: 틀린 내용과 아직 검증되지 않은 내용을 구분한다.
- `수정된 이해`: 무엇이 왜 바뀌었는지 초기 이해와 대응시킨다.
- `질문`: 해결 여부를 현재 conversation evidence로 판정한다.
- `AI 반도체 및 SSL 목표와의 연결`: 직접적인 연결이 있을 때만 작성한다. 억지 연결은 하지 않는다.
- `다음 행동`: 미해결 질문과 roadmap을 근거로 1~3개의 구체적 행동을 우선한다.
- `자기 설명 점검`: claim-evidence 기준으로 보수적으로 판정한다.
- `사용자 원문`: 중요한 자기 설명, 가설, 질문과 수정 발언을 의미를 바꾸지 않고 선택한다.

모든 section을 비슷한 길이로 채울 필요는 없다. evidence가 없으면 `아직 기록되지 않음` 또는 `없음`으로 둔다.

## 4. misconception correction을 보존한다

수정된 결론만 남기지 않는다. 다음 연결이 추적되어야 한다.

```text
사용자의 초기 설명 또는 가설
→ 무엇이 문제이거나 불확실했는가
→ 어떤 설명·예제·자기 설명으로 수정되었는가
→ 현재 어디까지 검증되었는가
```

초기 생각이 완전히 틀린 것이 아니라 부분적으로 맞았다면 정확한 부분과 보완된 부분을 분리한다. 사용자가 말하지 않은 오개념을 교육적 서사를 만들기 위해 추가하지 않는다.

## 5. mastery를 claim-evidence로 판정한다

checkbox 하나를 완료하려면 같은 세션 또는 확인된 관련 기록에 다음 중 하나가 있어야 한다.

- 사용자가 도움 없이 핵심 인과관계를 자기 말로 설명했다.
- 새로운 예제나 비교에 개념을 올바르게 적용했다.
- 이전 오해를 수정한 뒤 다시 설명해 일관성을 보였다.

단순 동의, 짧은 재진술, AI 설명 직후의 따라 말하기만으로는 완료하지 않는다. 범위가 넓은 checkbox는 일부 하위 개념을 설명했다는 이유로 완료하지 않는다. 미해결 질문이 해당 능력의 핵심 부분을 포함하면 checkbox를 열어 둔다.

## 6. 과거 기록의 사용 범위

과거 Learning Log에서 가져올 수 있는 것은 다음뿐이다.

- 현재 topic과 prerequisite
- 이미 확인된 이해와 아직 열린 질문
- 이번 기록과 연결할 실제 related note path
- 이전 이해와 현재 설명 사이의 변화 여부

과거 기록에서 가져오면 안 되는 것은 다음이다.

- 문장과 문단 구조
- 사용자 원문을 새 세션의 발언처럼 재사용하는 것
- 과거 checkbox 판정을 자동 승계하는 것
- 과거 주제의 개념 목록과 다음 행동을 현재 세션에 복제하는 것

## 7. 저장 전 quality review

- `system/LEARNING_LOG_METADATA_SCHEMA.json`을 실제로 읽고 Domain을 허용값 중 하나로 정확히 선택했는가?
- 각 주요 이해가 실제 사용자 evidence에 근거하는가?
- AI가 설명한 내용을 사용자의 mastery로 바꾸지 않았는가?
- 초기 이해, 불확실성, 수정된 이해가 서로 대응하는가?
- 해결·미해결 질문의 판정 근거가 있는가?
- checkbox마다 확인 가능한 evidence가 있는가?
- 사용자 원문이 현재 세션에서 나온 표현인가?
- 과거 좋은 기록의 문장과 서사를 모방하지 않았는가?
- 현재 세션에 불필요한 section 내용은 솔직하게 비워 두었는가?
